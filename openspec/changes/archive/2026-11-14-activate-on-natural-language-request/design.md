## Context

起動と終了の指示は `rikai-session-mode` の「起動と終了の指示を受け付ける」が定め、`SKILL.md` では冒頭と第6節が扱う。description は「/rikai」「rikaiを始めて」で起動し、「/rikai off」「rikai終了」で解除すると書いており、名指しなしの依頼には触れていない。それでも、iteration 3 の trigger 評価では名指しなしの依頼も発火した（proposal.md の Why）。モードが有効かどうかは会話の文脈で決まり、状態を持つ仕組みは無い。

## Goals / Non-Goals

**Goals:**

- 名指しなしの発話のうち、起動と終了に当たるもの、当たらないもの、判断できないものの扱いを決め、trigger 評価の期待値の根拠にする。

**Non-Goals:**

- 英語など、日本語以外の言語の名指しなしの依頼のケースを、評価データに足すこと。起動の条件は発話の意味で決めるので言語によらないが、今回の測定は日本語のケースに絞る。
- 名指しなしの二重起動を、`/rikai` の二重起動と別に扱うこと。有効中に起動に当たる発話をしたときは、`/rikai` と同じく二重起動として扱う。

## Decisions

### 起動の条件は「これからの回答ごとに確かめる」意図で決める

名指しなしの起動を、ユーザー自身がこれからの回答ごとに理解度を確かめることを求める発話に限る。

代替案との比較（design-rule の KISS・YAGNI の観点）:

- **キーワードで決める（「クイズ」「理解度」を含めば起動）**: 「クイズを10問作って」のような一回きりの依頼でも起動し、誤発火が増える。却下。
- **理解度の確認に関わる依頼を広く起動する**: 一回きりの診断も起動の対象になり、利用者が求めていない持続モードに入る。却下。
- **継続的な確認を求める意図で決める（採用）**: rikai がセッション持続モードであることと一致する。一回きりの依頼との境界もこの1つの条件で引ける。

### 判断できない起動の依頼には、1行の確認だけを返す

継続的な確認か一回きりかを判断できないときは、モードを始めるかを尋ねる1行だけを返し、依頼は返事を待ってから処理する。ユーザーが決めた。

- **起動しない**: 誤発火は無いが、起動を求めていた利用者は、`/rikai` を知らなければ起動できない。名指しなしの起動を認める目的に合わない。採用しなかった。
- **起動する**: 一回きりの依頼のつもりだった利用者が、持続モードに入る。却下。
- **確認の1行だけを返す（採用）**: 誤発火も起動の漏れも避けられる。依頼を先に処理すると、モードの内か外かで出力の形が変わるため、依頼は返事を受けてから処理する。肯定のあとは起動と同じ発言の依頼と同じ扱いにすれば、回答番号の規則（`rikai-question-selection`）を変えずに済む。

### 名指しなしの終了も認め、判断できないときは終了しない

起動を名指しなしで認める以上、終了も名指しなしで認める。ユーザーが決めた。起動の名前を知らずに始めた利用者が、終了の名前も知らないまま止められなくなるのを避ける。

- 判断できない発話では、確認せずにモードを続ける。起動とは扱いを変える。終了すると話題とレポートの状態が破棄され、取り消せないのに対し、続けた場合の害は、問いとレポートがもう1回付くことだけだからである。確認の1行を足すと、モード有効中の出力の順（`rikai-session-mode` の「毎回の出力を一定の順に並べる」）に新しい要素が増える。
- 今の問い1問だけを断る発話は、モード全体の停止ではないので、終了としない。

## Risks / Trade-offs

- [継続的か一回きりかの判断は、発話の解釈に依存する] → 境界のケースを `trigger-evals.json` と `evals.json` に足し、測定で確かめる。
- [起動の確認のあとの発言が、肯定とも否定とも取れない] → どちらでもなければ起動せず、その発言を通常どおり処理する。利用者は改めて頼むか、`/rikai` で起動できる。
- [Claude Code では、起動か判断できない依頼でスキルが読み込まれない（iteration 6・7 の trigger 評価で 0/3。description に確認の1文を足しても変わらなかった）] → 確認の1行は、スキルが読み込まれているときの挙動として仕様に残す。trigger 評価では、この依頼を `should_trigger: false` とする（ユーザーの判断）。読み込まれたときの挙動は `evals.json` で測る。
- [trigger 評価は1ターンで、モード有効中の名指しなしの終了は測れない] → 終了は、会話の要約を prompt に埋め込んだ `evals.json` のケースで測る。
- [description に条件を書き足すと長くなり、他のスキルとの選択に影響しうる] → 起動の条件と、起動しない代表例だけを書く。
