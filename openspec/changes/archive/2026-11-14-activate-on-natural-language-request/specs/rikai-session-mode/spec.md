## MODIFIED Requirements

### Requirement: 起動と終了の指示を受け付ける
rikai は、起動を `/rikai`、終了を `/rikai off` で受け付けなければならない（SHALL）。通常チャットでは、自然言語（「rikaiを始めて」「rikai終了」）でも切り替えられなければならない（SHALL）。（既定）

自然言語の起動と終了は、通常チャットでも Claude Code でも、rikai を名指ししない発話で受け付けなければならない（SHALL）。（確定）

- 起動に当たるのは、ユーザー自身がこれからの回答ごとに理解度を確かめることを求める発話とする（「理解度チェックしながら説明してほしい」「毎回クイズを出してほしい」「クイズで確かめてくれるモードにして」など）。
- モード有効中の、起動に当たる名指ししない発話は、`/rikai` と同じく二重起動として扱う。
- 次の発話は起動に当たらない。一回きりのクイズ作成や診断（「クイズを10問作って」「一度だけ診断して」など）、別の目的の一問一答（面接練習など）、rikai を話題や開発の対象にした発話、通常の解説の依頼。
- モードが有効でないときに、継続的な確認か一回きりかを判断できない発話（「理解できてるか確かめてほしい」など）を受けたら、回答ごとに理解度を確かめるモードを始めるかを尋ねる1行だけを、ユーザーの発言の言語で返す。この応答はモードの外で、回答本文もレポートも問いも付けず、依頼は処理しない。次の発言が肯定なら起動として扱い、保留した依頼を起動と同じ発言の依頼として処理する。肯定の発言に別の依頼も含まれるときは、保留した依頼とあわせて、起動と同じ発言の依頼として1つの回答（回答番号 1）で処理する。否定なら起動せず、保留した依頼を通常の回答として処理する。一回きりを選ぶ返事（「一度だけでいい」など）は、否定として扱う。どちらでもなければ起動せず、その発言を通常どおり処理する。モード有効中の同じ発話は起動にも終了にも当たらない発話として、通常のターンで処理する。
- 上の確認は、スキルが読み込まれているときの挙動とする。Claude Code では、この種の発話でスキルが読み込まれず、確認を出さずに通常どおり答えることがある（trigger 評価で確認した）。
- 終了に当たるのは、モード有効中に、ユーザー自身が回答ごとの問いとレポートの停止を求める発話とする（「もうクイズはいらない」「理解度チェックはもうやめて」など）。
- 次の発話は終了に当たらない。今の問い1問だけを断る発話（「この問いはパス」など）、rikai を話題にしただけの発話。
- 終了か判断できない発話では終了せず、モード有効中の通常のターンとして処理する。終了すると話題とレポートの状態が破棄され、取り消せないため。
- モードが有効でないときの名指しなしの終了に当たる発話は、rikai の指示として扱わず、通常どおり処理する。

スキルの frontmatter に `name: rikai` を置き、プラグインの名前空間なしの `/rikai` でも呼べるようにする。同名の別コマンドとぶつかる場合は、`/rikai:rikai` で呼ぶ。（確定。公式ドキュメントに基づく。`claude -p --plugin-dir` で、`/rikai` と入力するだけでスキルが起動することを確認した）

終了の指示は、ユーザー自身がモードの終了を命じる発話か、回答ごとの問いとレポートの停止を求める発話に限る。rikai を話題にしただけの発話（「rikaiの終了条件を教えて」など）は、終了として扱わない。（確定）

すでにモードが有効なときの `/rikai` は、状態をリセットせず、すでに有効である旨を1行で伝える。モードが有効でないときの `/rikai off` は、有効ではない旨を1行で伝える。（確定）

#### Scenario: コマンドによる起動
- **WHEN** ユーザーが `/rikai` を送る
- **THEN** モードが有効になる

#### Scenario: コマンドによる終了
- **WHEN** モード有効中にユーザーが `/rikai off` を送る
- **THEN** モードが解除される

#### Scenario: 通常チャットでの自然言語による切り替え
- **WHEN** 通常チャットでユーザーが「rikaiを始めて」または「rikai終了」と送る
- **THEN** モードが有効または解除される

#### Scenario: 名指しなしの起動
- **WHEN** モードが有効でないときに、ユーザーが「理解度チェックしながらRustの所有権を説明してほしい」と送る
- **THEN** モードが有効になり、依頼を起動と同じ発言の依頼として処理する

#### Scenario: 一回きりのクイズの依頼
- **WHEN** モードが有効でないときに、ユーザーが「Pythonのasyncioについてクイズを10問作って」と送る
- **THEN** モードは有効にならず、依頼を通常どおり処理する

#### Scenario: 起動か判断できない依頼
- **WHEN** モードが有効でないときに、ユーザーが「Reactのhooks、ちゃんと理解できてるか確かめてほしい」と送る
- **THEN** モードを始めるかを尋ねる1行だけを返し、回答本文、レポート、問いは付けない

#### Scenario: 起動の確認への肯定
- **WHEN** 起動の確認にユーザーが肯定で答える
- **THEN** モードが有効になり、保留した依頼を起動と同じ発言の依頼として処理する

#### Scenario: 起動の確認への否定
- **WHEN** 起動の確認にユーザーが否定で答える
- **THEN** モードは有効にならず、保留した依頼を通常の回答として処理する

#### Scenario: 名指しなしの終了
- **WHEN** モード有効中に、ユーザーが「もうクイズはいらない」と送る
- **THEN** モードが解除され、終了の応答を返す

#### Scenario: 今の問いだけを断る発話
- **WHEN** モード有効中に、ユーザーが「この問いはパス」と送る
- **THEN** モードは解除されず、通常のターンとして処理する

#### Scenario: 二重起動
- **WHEN** モード有効中にユーザーが `/rikai` を送る
- **THEN** 回答番号とレポートをそのまま続け、すでに有効である旨を1行で伝える。同じ発言に依頼が含まれる場合は、その1行のあと、依頼を通常の回答として処理する

#### Scenario: 有効でないときの終了
- **WHEN** モードが有効でないときにユーザーが `/rikai off` を送る
- **THEN** 有効ではない旨を1行で伝える
