## Context

`SKILL.md` は、問いの種別とファイル保存の案内を「Claude Code で動いているか」で分けている。Claude Code では `pick.mts` で乱数を引き、それ以外では直前の問いの逆で決める。起動時には「チャット内」と「`.rikai/<topic>-rikai-report.md` に保存」の2択を提案する。

claude.ai のチャットでは、`${CLAUDE_SKILL_DIR}` が `/root/.claude/skills/synced/<id>/rikai` に置き換わり、Bash と Node もある。モデルはこの環境を Claude Code と判断して `pick.mts` を実行し、同梱されないスクリプトの失敗が表示される。#25 で「迷ったら Claude Code 以外」と書いたあとも再発した。

`rikai.zip` は `rikai/SKILL.md` だけを含み、plugin 版と同じ `SKILL.md` を配る。v1.0.0 は未リリース。

## Goals / Non-Goals

**Goals:**

- 環境を見分けなくても正しく動くように、問いの種別とファイル保存の案内から、Claude Code かどうかの判断を無くす。
- plugin 版と ZIP 版で、同じ `SKILL.md` を使い続ける。
- 種別を機械的に選ぶ要件と、ファイル保存の機能そのものは保つ。

**Non-Goals:**

- 文脈から種別を決める方式の検討（#47 で扱う）。
- 回答番号の数え方、判定、レポートの項目の変更。
- `scripts/build-zip.mts` の変更。

## Decisions

### 種別は全環境で直前の問いの逆にする

すでに仕様にある、スクリプトが使えない環境向けの決め方を全環境に広げる。直前が質問提案ならクイズ、クイズなら質問提案、起動後の最初は質問提案にする。

- 代替案A: `SKILL.md` の指示を強める。#25 の対策のあとも再発しており、モデルの判断に頼る点が変わらない。採らない。
- 代替案B: ZIP を作るときに `SKILL.md` から Claude Code だけの手順を取り除く。plugin 版と ZIP 版の内容が分かれ、目印と変換の仕組みが増える（KISS に反する）。採らない。
- 代替案C: 文脈で種別を決める。機械的に選ぶ確定要件を外すことになり、偏りへの対策が要る。#47 で別に検討する。
- 採る案は環境の判定、実行の失敗の扱い、スクリプト本体とテストをまとめて無くせる（KISS、YAGNI）。失うのはランダムさだけで、交互でも同じ種別が続かないという目的は満たす。

### スクリプトとテストを削除する

`skills/rikai/scripts/`（`pick.mts`、`cli.mts`、`utils/randomPick.mts`）は `pick.mts` のためだけにある。`__tests__/pick.test.mts`、`__tests__/utils/randomPick.test.mts`、ヘルパーの `createPickResult` も削除する。`__tests__/helpers/scriptTestHelpers.mts` の残りは `build-zip.test.mts` が使うので残す。`tsconfig.json` の include から `skills/rikai/scripts/**/*.mts` を外す。`SKILL.md` の `allowed-tools` も不要になるので削除する。

### 起動時は保存を頼めることだけを伝える

起動時の案内は全環境で「レポートはチャット内に出す。ファイルに保存したいときは伝えてほしい」の旨だけにし、保存先のパスは示さない。保存を頼まれたら保存先を決める。場所の指定が無ければ `.rikai/<topic>-rikai-report.md` にし、指定があればその場所に置く（`.rikai/.gitignore` は作らない）。

- 代替案A: Claude Code だけで提案する。claude.ai で誤って提案するおそれが残る。採らない。
- 代替案B: ファイル保存を廃止する。確定した機能を削ることになり、変更が大きい。採らない。
- 採る案は案内を環境で分けないので判断を誤らない。書けるかどうかの判断は、利用者が保存を頼んだときだけに限られる。

### 書けない環境では伝えてチャット内で続ける

保存を頼まれても、利用者が後から開けるファイルを書けない環境（claude.ai のチャットなど）では、保存できない旨を1行で伝え、チャット内表示で続ける。既存の「書き込みに失敗したらそのターンはチャットに出す」の扱いと向きをそろえる。

### バージョン

v1.0.0 は未リリースなので、この変更は v1.0.0 に含め、`version` は 1.0.0 のままにする。リリース済みであれば、乱数の要件の削除は major に当たる（`release.md` の SemVer の判定）。

## Risks / Trade-offs

- Claude Code では、問いの種別の並びが読める（交互になる）。→ 種別以外の種類と形式は文脈で選ぶので、単調さは小さい。文脈で決める方式は #47 で検討する。
- claude.ai で保存を頼まれたとき、モデルがサンドボックスに書けると判断して保存したと答えるおそれがある。→ 仕様のシナリオで claude.ai のチャットを書けない環境の例として挙げる。頼まれたときだけの判断なので、起動のたびに誤ることはない。
- 指定された場所への保存は、`.rikai/` の規則（話題の再開時の検索、ファイル名の作り方）をその場所に読み替える。読み替えで足りない点は実際の使われ方を見て別の issue で扱う。
