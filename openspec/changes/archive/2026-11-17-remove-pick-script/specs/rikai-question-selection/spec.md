## REMOVED Requirements

### Requirement: 質問提案とクイズの別と回答番号を決める
**Reason**: 乱数で種別を決める `pick.mts` を廃止し、全環境で直前の問いの逆にするため（#46）。乱数の閾値、スクリプトの実行と失敗の扱い、Claude Code かどうかの判断のシナリオを、要件ごと置き換える。
**Migration**: 「質問提案とクイズを交互に出し、回答番号を決める」に移す。回答番号の数え方は変えない。

## ADDED Requirements

### Requirement: 質問提案とクイズを交互に出し、回答番号を決める
rikai は、質問提案とクイズのどちらを出すかを、機械的に選ばなければならない（SHALL）。（確定）

全環境で、直前に出した問いの種別と逆にする。直前が質問提案ならクイズ、クイズなら質問提案とする。起動後の最初の問いは、質問提案とする。（確定。回答番号を進めないターンが出ても、同じ種別が続かないようにするため）スクリプトで乱数を引く方式は使わない。（確定。claude.ai のチャットでは Claude Code と見分けられず、同梱されないスクリプトを実行して、その失敗がツール呼び出しの表示として利用者に見えたため）

「直前に出した問い」は、そのモードで最後に出した問いとする。終了後に再び起動したときは、直前の問いは無いものとして、最初の問いから数え直す。（確定）

回答番号は、rikai の起動後の回答のうち、数えるものに付ける会話全体の通番とする。数えるのは、ユーザーの発言に、前回の問いへの返答（クイズの回答、提案された質問、言い換え）、問いとは無関係な仮説、詳細を詰める型の質問のいずれかが含まれるターンの回答である。これらのどれも含まれないターンの回答は、数えない（番号を進めない。回答本文、レポート、問いはこれまでどおり出す）。ただし、起動の後、数えた回答がまだ無いときは、返答も仮説も質問も含まなくても、次の回答を数える。起動と同じ発言に含まれる依頼への回答、起動の次の発言への回答、最初の回答より前の二重起動の発言に含まれる依頼への回答は、いずれもこの例外に当たる。数えた回答がすでにあるときの二重起動の発言に含まれる依頼への回答は、この例外に当たらず、上の条件で判定する。（確定）通番は表示用なので、上の条件で数えるかの判定に迷ったときは、数えなくてよい（上の例外には当てはまらない）。（既定）

起動後の最初に数える回答を 1 とし、以後は直前に数えた回答の番号に 1 を足す。上の例外により、起動後の最初の回答が 1 になる。起動を知らせる応答、二重起動を知らせる応答、終了の応答も数えない。同じ発言の依頼への回答は、これらの応答とは別に、上の例外と条件で判定する。ユーザーの発言1回につき、数えるターンの最終の回答を1つ数え、ツール実行中の中間メッセージは数えない。話題が分かれても番号は共有する。終了後に再び起動したときは、1 から数え直す。終了の応答の最終レポートには、直前に数えた回答の番号を書く。数えた回答が無いまま終了したときは、最終レポートを出さない（rikai-session-mode に従う）ため、番号の無いレポートは生じない。（確定）

機械選択の対象は、質問提案とクイズの別だけである。質問提案の中の種類とクイズの形式は、内容に応じてAIが選ぶ。（既定）会話圧縮や `/clear` の後に回答番号と直前の問いを維持できるかは未決である。

#### Scenario: 直前の問いが質問提案
- **WHEN** 直前に出した問いが質問提案である
- **THEN** クイズを出す

#### Scenario: 直前の問いがクイズ
- **WHEN** 直前に出した問いがクイズである
- **THEN** 質問提案を出す

#### Scenario: 回答番号を進めないターンが続く
- **WHEN** 回答番号を進めないターンが続き、そのたびに問いを出す
- **THEN** 質問提案とクイズを交互に出し、同じ種別を続けて出さない

#### Scenario: コードを実行できる環境
- **WHEN** Claude Code や、claude.ai のチャットのように、Bash ツールや Node がある環境で問いの種別を決める
- **THEN** スクリプトを実行せず、直前の問いの種別と逆で決める

#### Scenario: 起動後の最初の問い
- **WHEN** rikai を起動した後、最初の問いを出す
- **THEN** 質問提案を出す

#### Scenario: 起動と同じ発言への回答
- **WHEN** 新しく起動するときに、「rikaiを始めて。Xを説明して」のように、起動と同じ発言に依頼が含まれる
- **THEN** その依頼への回答は、返答も仮説も含まなくても数え、回答番号は 1 になる

#### Scenario: 起動の次の発言への回答
- **WHEN** `/rikai` だけを送り、次の発言で、返答も仮説も質問も含まない依頼だけを送る
- **THEN** その依頼への回答を数え、回答番号は 1 になる

#### Scenario: 最初の回答より前の二重起動
- **WHEN** `/rikai` だけを送り、次の発言で「rikaiを始めて。Xを説明して」と送る
- **THEN** 状態をリセットせず、Xへの回答を数え、回答番号は 1 になる

#### Scenario: 二重起動の発言に含まれる依頼
- **WHEN** 数えた回答がすでにあり、有効なときに、「rikaiを始めて。Xを説明して」のように、二重起動の発言に依頼が含まれ、返答も仮説も含まれない
- **THEN** 状態をリセットせず、この依頼への回答は数えない（回答番号を進めない）

#### Scenario: 返答も仮説も質問も含まないターン
- **WHEN** 起動後の2回目以降で、ユーザーの発言に、前回の問いへの返答も、問いとは無関係な仮説も、詳細を詰める型の質問も含まれない
- **THEN** 回答番号を進めない。回答本文、レポート、問いは通常どおり出す

#### Scenario: 返答を含むターン
- **WHEN** ユーザーの発言に、前回の問いへの返答が含まれる
- **THEN** 回答番号を1進める

#### Scenario: 回答番号に数えない応答
- **WHEN** 起動を知らせる応答、二重起動を知らせる応答、または終了の応答を返す
- **THEN** 回答番号に数えない。終了の応答の最終レポートには、直前に数えた回答の番号を書く
