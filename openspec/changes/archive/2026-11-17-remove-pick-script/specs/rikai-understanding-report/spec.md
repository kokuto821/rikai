## MODIFIED Requirements

### Requirement: レポートの形式と更新
rikai は、理解度レポートを、デフォルトではチャット内の Markdown コードブロックとして出力しなければならない（SHALL）。代替として、ユーザーが保存を頼んだときは、Markdown ファイルに保存できなければならない（SHALL）。毎回、前回のレポートを前提に更新しなければならない（SHALL）。（確定）

保存先は保存を頼まれたときに決める。ユーザーが場所を指定しなければ、`.rikai/<topic>-rikai-report.md` に保存する。（既定）ユーザーが別の場所を指定したときは、保存先のディレクトリと、話題を再開するときに探す場所だけを、その場所に読み替える。ファイルのパスで指定されたときは、そのディレクトリを使い、ファイル名は `<topic>` の規則で作る。この場合、`.rikai/` と `.rikai/.gitignore` は作らない。（既定）

利用者が後から開けるファイルを書けない環境（claude.ai のチャットなど）で保存を頼まれたときは、保存できない旨を1行で伝え、チャット内表示で続けなければならない（SHALL）。書けるか迷ったら、書けない環境として扱わなければならない（SHALL）。（確定。誤って保存に切り替えると、レポートがチャットに出なくなり、利用者がファイルも開けず、内容を失うため）起動時の案内は rikai-session-mode に従う。

#### Scenario: デフォルトの形式
- **WHEN** ユーザーが保存を頼まない
- **THEN** チャット内の Markdown コードブロックで出力する

#### Scenario: ファイルへの保存
- **WHEN** ユーザーが場所を指定せずに、ファイルへの保存を頼む
- **THEN** `.rikai/<topic>-rikai-report.md` に保存する

#### Scenario: 保存先を指定した保存
- **WHEN** ユーザーが場所を指定して、ファイルへの保存を頼む
- **THEN** 指定した場所に `<topic>-rikai-report.md` を保存し、`.rikai/` と `.rikai/.gitignore` は作らない

#### Scenario: ファイルを書けない環境での保存の依頼
- **WHEN** claude.ai のチャットのように、利用者が後から開けるファイルを書けない環境で、ファイルへの保存を頼まれる
- **THEN** 保存できない旨を1行で伝え、チャット内表示で続ける

#### Scenario: 前回のレポートの更新
- **WHEN** 前回のレポートが存在する状態で、新しいレポートを出力する
- **THEN** 前回のレポートを前提に更新する

#### Scenario: 書けるか迷う環境での保存の依頼
- **WHEN** ファイルを書けるかを判断できない環境で、ファイルへの保存を頼まれる
- **THEN** 書けない環境として扱い、保存できない旨を1行で伝え、チャット内表示で続ける
