## Context

rikai は通常のチャットでも `SKILL.md` だけで動く。スクリプトを持たないので、`.rikai/` の作成も、`SKILL.md` の手順として AI が行う。現行の仕様と `SKILL.md` は、`.rikai/` を相対パスで書いていて、作成の起点を決めていない。動機は proposal.md を参照する。

## Goals / Non-Goals

**Goals:**
- 初回保存で `.rikai/` が自分自身を git の対象から外す。
- ユーザーが `.rikai/.gitignore` を消せば、追跡に切り替えられる。

**Non-Goals:**
- フラグと `statusline.mts` の置き場の変更（`${CLAUDE_CONFIG_DIR:-~/.claude}/rikai/` のまま）。
- 設定ファイルの追加。設定項目が出たときに、同じ `.rikai/` に追加する。
- スクリプトやテストの追加。

## Decisions

- **`.rikai/` の中に `.gitignore`（`*`）を置く。** 代替案は、リポジトリ直下の `.gitignore` への追記。「直下の `.gitignore` を自動編集しない」方針に反するので採らない。リポジトリごとの初期化コマンドを設ける案は、ユーザーの手間が増え、`SKILL.md` だけで完結させる方針に合わないので採らない。
- **作る条件は「初めて `.rikai/` を作るとき」にする。** `.rikai/` か `.rikai/.gitignore` がすでにあれば何もしない。代替案は、保存のたびに `.rikai/.gitignore` の有無を確認して作り直す案。ユーザーが意図して消した場合に、勝手に除外へ戻すので採らない。追跡したいユーザーの操作は、ファイルの削除だけで済む。
- **作成の起点は cwd にする。** 代替案は、git のルート。サブディレクトリで起動しても `.rikai/` が増えない利点があるが、git 管理外の場所では別の規則が要り、`SKILL.md` に手順が増える。git の状態に依存しない単純さを選んだ。サブディレクトリで起動すると、そこに `.rikai/` ができる点は、リスクとして受け入れる。
- **通知は1行にして、付随の通知に数える。** 初回保存時の案内（追跡か除外かを決められる旨）を、作ったことの通知に置き換える。通知の位置と数え方は、これまでの付随の通知に従う。保存先の案内ではないので、ファイル保存中のチャットにも出す。
- **`.rikai/.gitignore` を作れなかったときは、レポートの書き込み失敗と同じに扱う。** `.rikai/.gitignore` を先に作り、作れなければレポートをファイルに書かず、チャットに出す。失敗のまま保存を続けると、レポートが追跡の対象になりうるため。新しい通知の種類は増やさず、既存の書き込み失敗の1行に含める。
- **表記を `.rikai/.gitignore` に統一する。** 直下の `.gitignore` と取り違えないため。仕様の2つの要件と `SKILL.md` の第1節・第5節が対象。

## Risks / Trade-offs

- [cwd がリポジトリのルートでないと、サブディレクトリに `.rikai/` ができる] → 受け入れる。移動すれば直せる。既存の挙動（相対パス）と変わらない。
- [AI が `.rikai/.gitignore` の作成を飛ばすことがある] → 受け入れる。影響は、レポートが追跡の対象に残るだけで、リポジトリ直下は壊れない。この振る舞いは `SKILL.md` の散文だけで担う方針（Context）による。
- [`.rikai/` は作れたが `.rikai/.gitignore` だけ作れなかった場合、次の保存以降は「`.rikai/` がある」として扱われ、`.rikai/.gitignore` の無いまま保存が続く] → 受け入れる。部分失敗は稀で、ユーザーには失敗した1ターン目に1行で伝わる。影響は、レポートが追跡の対象に残るだけである。条件を「`.rikai/` にファイルが無いとき」に広げれば塞げるが、「消されても作り直さない」の判定が複雑になるので、今回は採らない。
- [ユーザーが `.rikai/.gitignore` を消すと、レポートが追跡の対象になる] → 意図した操作とする。通知の文言に、消せば追跡できると書く。
- [#10（未マージ）が `SKILL.md` と `rikai-session-mode` の仕様を同時に変えている] → この change の delta は、付随の通知の1語と第5節の1行にしか触れない。#10 のマージ後に衝突が出たら、後から出す側が追従して解消する。
