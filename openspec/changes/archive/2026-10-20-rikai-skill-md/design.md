## Context

動機は proposal.md の Why を参照する。

- 振る舞いの仕様は `openspec/specs/` の5つ、スクリプトは `skills/rikai/scripts/`（#3）にある。`SKILL.md` と manifest が無い。
- 前提となる設計は、`archive/2026-10-15-rikai-skill-spec/design.md` にある。コアは `SKILL.md` だけで完結させ、スクリプト・バッジ・ファイル保存は Claude Code 向けの任意層とする。
- 外部仕様は、公式ドキュメント（2026-10-19 に確認）による。
  - プラグインのスキルは `/plugin-name:skill-name` で呼ぶ。frontmatter に `name` を置くと、bare の `/name` でも呼べる。他のコマンドが同名を使っていない場合に限る。
  - `${CLAUDE_SKILL_DIR}` は、スキル本文と `allowed-tools` の Bash ルールで展開される。`${CLAUDE_SESSION_ID}` は本文で使える。
  - `plugin.json` で必須なのは `name` だけ。`version` を設定すると、その値を変えるまで利用者に更新が届かない。
  - vitest 5.0.5 の Node 要件は `^22.12 || ^24 || >=26`。想定する最小バージョン 22.18 と矛盾しない。

## Goals / Non-Goals

**Goals:**

- 頻出するのに決まっていない振る舞いを、`SKILL.md` に書く前に決め、spec へ戻す。
- `SKILL.md` を単一ファイルで完結させる。スクリプトが使えない環境でも、偶奇で動く。

**Non-Goals:**

- 未決事項のすべてを決めない。会話圧縮後のモード維持、フラグの掃除、`.rikai/` の gitignore と起点などは、未決のまま残す。
- `version` と `LICENSE` を決めない。
- スクリプトとそのテストを変えない。

## Decisions

### 未決事項は、実装に必要な最小限だけ決める

`SKILL.md` は指示文なので、頻出するのに決まっていない項目は、書く前に決める。それ以外は未決のまま残し、`SKILL.md` に書かない。

- 代替案1: 未決を決めず、AIの判断に任せる。返答のみのターンや終了時の応答など、頻出ケースの挙動が毎回ぶれる。
- 代替案2: Open Questions をすべて決める。範囲が issue を大きく超える。

### コマンド名は frontmatter の `name: rikai` で `/rikai` を通す

`name: rikai` を置き、`/rikai` と `/rikai off` を正式な綴りとする。`$ARGUMENTS` が `off` かで起動と終了を分ける。`/rikai:rikai` は、同名コマンドとぶつかったときの代替として README に書く。`disable-model-invocation` は付けない（通常チャットで自然言語から起動するため）。

- 代替案: `/rikai:rikai` を正式な綴りにする。spec の `/rikai` と食い違い、入力も長くなる。

### `allowed-tools` は `pick.mts` と `flag.mts on|off` だけを許可する

```yaml
allowed-tools: Bash(node ${CLAUDE_SKILL_DIR}/scripts/pick.mts) Bash(node ${CLAUDE_SKILL_DIR}/scripts/flag.mts on *) Bash(node ${CLAUDE_SKILL_DIR}/scripts/flag.mts off *)
```

`flag.mts install` は載せないので、実行時に確認が出る。本文には、確認で拒否されたら実行せず終える旨を書く。`pick.mts` は引数なしで実行する。`pick.mts *` は、テスト用の乱数引数まで事前承認してしまうため載せない（レビューの指摘）。許可ルールは、`SKILL.md` の本文が指示するコマンドと一致させる。ファイル保存（`.rikai/` への書き込み）は事前承認せず、都度の承認に任せる。

### `pick.mts` が連続2回失敗したら、そのセッションは偶奇のみにする

失敗は黙って偶奇に落とし、次のターンは再試行する。連続2回失敗したら、以後は試さない。許可されない環境や Node が無い環境で、毎ターン失敗する呼び出しと権限プロンプトが繰り返されることを避けるため（レビューの指摘）。

- 代替案: 毎ターン再試行する。失敗のたびにツール出力が文脈に積まれる。
- 代替案: 1回の失敗で以後試さない。一時的な失敗でも、以後ずっと偶奇になる。

### `SKILL.md` は、毎ターンの出力契約を先頭近くに置く

持続モードでは、毎ターンの指示が文脈の遠い位置に押しやられて薄れる。毎ターン必要な内容（処理の手順、出力の順、問いの選び方、判定）を先頭近くにまとめ、起動・終了・ファイル保存・ファイル名の規則は後段へ回す。単一ファイルのまま並べ替えるだけで、`rules/` などへは切り出さない。出力の形（問いの専用セクションなど）を毎回固定し、その形自体が次のターンのリマインダになるようにする。

- 代替案: Claude Code 専用の記述を `references/` に切り出す。「`SKILL.md` だけで完結」の確定事項に反する。
- 候補（別 issue）: フラグを読む UserPromptSubmit フックで、毎ターン短いリマインダを注入する。フラグを表示専用とした決定を見直す必要があり、今回は扱わない。

### 回答番号は会話全体の通番とする

話題が分かれても番号を共有し、レポートの `回答番号` に現在の通番を書く。

- 代替案: レポート単位で数える。話題の切替で番号が戻り、通常チャットの質問提案とクイズが偏る。

保持は、前回のレポートの値に 1 を足す方法にする。専用のカウンタは持たない。

### 「返答なし」は、前回の問いへの返答の有無で決め、記録先は話題で分ける

判定を2段階に分ける。(1) 前回の問いへの返答があるかを見る。無く、前回の問いが残っていれば、出題元の話題に返答なしを記録する。(2) 問いとは無関係な仮説や質問があれば、その対象の話題のレポートに判定を記録する。話題Aの問いが残っていて、話題Bの認識確認をした場合、Aに返答なし、Bに判定が記録される。

- 代替案: 「別の話題に移った」と判断したときだけ返答なしにする。話題の判断が曖昧で、AIの判断がぶれる。

### フラグとバッジは表示専用とし、モードの復元はしない

モードの実体は会話の文脈にある。フラグは `statusline.mts` だけが読む。`flag.mts` が失敗しても、モードには影響させない。会話圧縮や `/clear` によるリセットは許容し、復元の仕組み（`flag.mts status` など）は設けない。

- 代替案: フラグを状態の保持に使い、読み取りコマンドを足す。スクリプトの変更と `rikai-badge` の仕様変更が要る。`/clear` でセッション ID が変わるため、救えない場合もある。圧縮後にスキルの指示が再注入されるかも未確認。先に実機で観察し、必要なら別 issue にする。

### 併用スキルの文体に関する要件を削除する

`rikai-session-mode` の「併用スキルの文体に関わらず追加セクションを通常の日本語で書く」を REMOVED とし、`SKILL.md` からも外す。この指示は効力がベストエフォートで、文体を変えるスキルの毎ターンの注入に対しては保証できない。README には注意書きだけ残す。`.claude/rules/genshijin-priority.md` は、spec への参照を外して、開発セッションの圧縮の除外を引き続き定める。

- 代替案: `SKILL.md` にだけ残す。spec と食い違う。
- 影響: genshijin などと併用すると、判定結果・レポート・問いも圧縮されうる。

### manifest は最小構成とする

`plugin.json` は `name`、`description`、`author`（`name`）、`repository` だけを置く。`version` と `license` は置かない（運用が未決のため）。`marketplace.json` は、リポジトリのルートを `source` とする1プラグインの構成にする。スキーマは、書く前に公式ドキュメントで確認する。

### #6 とは分離し、現行 spec のまま書く

`.rikai/` の gitignore の案内は、現行 spec（初回保存時に1行案内し、`.gitignore` は編集しない）のまま `SKILL.md` に書く。#6 では、この1節だけを差し替える。

- 代替案: #6 を先に済ませる。#6 は未確定事項が多く、#4 の着手が遅れる。

## Risks / Trade-offs

- [bare の `/rikai` が通らない（他のコマンドと衝突する）] → README に `/rikai:rikai` を書く。`claude -p --plugin-dir` で `/rikai` が起動することは確認した（2026-10-19）。他のコマンドと衝突する環境は、引き続き `/rikai:rikai` で回避する。
- [`allowed-tools` の許可が、期待どおりに効かない] → `flag.mts on ${CLAUDE_SESSION_ID}` が、非対話モードで確認なしに実行され、`${CLAUDE_SESSION_ID}` が展開されることは確認した（2026-10-19）。`pick.mts` の許可と、`flag.mts install` の確認は、対話セッションで確認する。
- [statusline の連結例が、実環境で動かない] → あなたの環境で genshijin と連結して確認してから、README に載せる。
- [`SKILL.md` が長くなり、指示が守られにくくなる] → 毎ターンの出力契約を先頭近くに置く。`ai-engineering-review` でレビューする。実装時点の `SKILL.md` は 157 行で、これを基準値とする。
- [`marketplace.json` の `source: "./"` だと、リポジトリ全体（`openspec/`、`__tests__/`、`.claude/` など）が配布物に入る可能性がある] → `claude plugin install` を実際に実行して、含まれるファイルを確認する。多すぎるなら、`source` のディレクトリを分けるか、除外の方法を検討する。
- [長いセッションでレポートの出力が増え続ける] → 出力するのは、そのターンの話題と判定や返答なしを記録した他の話題のレポートだけにする（終了時を除く）。1箇所1行で更新する。上限は未決のまま残す。
- [会話圧縮でモードが失われる] → 許容する。再度 `/rikai` で起動する旨を `SKILL.md` に書く。
- [#4 と #6 が `SKILL.md` の同じ節を触る] → #4 のマージ後に #6 に着手する。

## Open Questions

- 会話圧縮後に、スキルの指示が再注入されるか（モードが維持されるか）。実機で観察する。
- 22.18 での型除去の既定化（`.mts` の直接実行）。公式の変更履歴で最終確認する。
- `marketplace.json` の `description` と `author` が `plugin.json` と重複している。将来ずれうるので、片方に寄せるかを、配布範囲の確認と合わせて決める。
- 20ターン以上のセッションで、問いの付与率とレポートの出力順の遵守率が保たれるか。実機で観察する。
