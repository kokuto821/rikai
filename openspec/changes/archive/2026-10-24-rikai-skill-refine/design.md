## Context

動機は proposal.md の Why を参照する。現状の仕様では、全ターンで回答番号を1進め、通常チャットでは回答番号の偶奇で問いの種別を決める。ファイルに保存していても、チャットにレポートを出す。

`skills/rikai/SKILL.md` は、通常のチャットに貼っても動くよう、全ルールを1ファイルに集約している。仕様を変えたら、`SKILL.md` の第1・2・4・5・6節と、図（フローチャート）を揃える必要がある。

`.rikai/.gitignore` の自動作成は #6 で扱う。ファイル保存の手順は、#6 と同じ節にある。

## Goals / Non-Goals

**Goals:**
- 回答番号を、返答や仮説のあったターンの通番として読めるようにする。
- 返答のないターンでも、理解負債（返答なし）がレポートで見える状態を保つ。
- ファイルに保存している間の、チャットの出力を減らす。

**Non-Goals:**
- `.rikai/.gitignore` の作成（#6）。
- スクリプト（`pick.mts`、`flag.mts`、`statusline.mts`）の変更。
- サジェストの内容や表示の制御（スキルからは制御できない）。

## Decisions

### 回答番号だけを止める

返答も、仮説も、詳細を詰める型の質問もないターンでは、回答番号を進めない。判定結果は、元から出ない。レポートと問いは出し続ける。

- 理由: 前回の問いに返答がないターンは、「返答なし」が記録されるターン（理解負債が増えるターン）でもある。レポートを止めると、その記録が見えなくなる。要望の中心は、回答番号の更新だったので、番号だけを止める。
- 代替案: 番号、レポート、問いをすべて止める案（理解負債を見落とす）。レポートを、変化があったときだけ出す案（今の「変化がなくても出す」規則に例外が増える。ノイズが気になったら、後から寄せられる）。

### 起動と同じ発言への回答は数える

起動直後の1回は、返答も仮説もないが、回答番号 1 として数える。

- 理由: 現行の仕様がすでにそう定めており、「最初の回答は 1」という説明が変わらない。例外は、定義の中に1行で収まる。
- 代替案: 起動直後も数えない案。最初のレポートが出る時点が、返答のあった最初のターンまで遅れ、番号の起点も分かりにくくなる。

### 通常チャットでは、直前の問いと逆にする

偶奇の判定をやめ、通常チャットとスクリプト失敗時のフォールバックでは、直前に出した問いと逆の種別にする。最初の問いは質問提案にする。

- 理由: 回答番号を進めないターンでも問いを出すので、番号の偶奇では、同じ種別が続く。問いの履歴だけで決めれば、数えるターンの定義に左右されない。回答番号は、レポートの通番としてだけ使う。
- 代替案: 問いを出した回数を別に数える案（数える対象が増える）。偶奇のまま、同じ種別が続くのを許す案（問いの偏りが出る）。
- 関連: Claude Code の乱数による選択は変えない。

### ファイル保存中は、チャットに何も出さない

ファイル保存中は、通常のターンで、レポートも保存先の案内も出さない。終了の応答では、最終レポートの代わりに、保存したファイルのパスを1行で並べる。

- 理由: 内容は、ファイルとその差分の履歴で見られる。チャットに出すと、同じ内容が二重になる。終了時のパスの一覧がないと、ファイルの場所が分からなくなる。
- 代替案: 終了時も何も出さない案（場所が起動時の提案だけになる）。終了時だけ最終レポートを出す案（二重になる）。

### サジェストは、スキルでは扱わない

入力欄のサジェストは、Claude Code 本体の機能で、会話履歴から、同じモデルが裏で生成する。公式ドキュメントでは、スキルや hooks から、特定のターンだけ抑える方法も、内容に影響を与える方法も確認できなかった。利用者側の設定（`/config` の Prompt suggestions、`promptSuggestionEnabled: false`、環境変数 `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`）で無効にできる。README の「他のスキルとの併用」に案内する。

- 理由: プラグインが、利用者の設定を書き換えるのは避ける。仕様に書くと、スキルが保証できない内容を約束することになる。
- 代替案: このリポジトリの `.claude/settings.json` にも設定を置く案（開発セッションでしか効かない）。別 issue に切り出す案（調査の結論は変わらない）。

## Risks / Trade-offs

- [数えるターンの判定が曖昧になる。仮説や質問が含まれるかをAIが判断するため] → 数えるのは、返答、仮説、詳細を詰める型の質問のいずれかが含まれるときに限る。判断に迷うときは数えなくてよい。数えなくても、レポートと問いは出るので、影響は小さい。
- [会話圧縮で直前の問いを失うと、最初の質問提案に戻る] → 回答番号も同じ圧縮で失われる。条件は変わらない。
- [`SKILL.md` と仕様、図の食い違い] → タスクで、第1・2・4・5・6節と図を、まとめて直す。レビューで突き合わせる。
- [#6 と同じ節（ファイル保存の手順）を触る] → この change を先にアーカイブするか、着手の順を合わせる。
