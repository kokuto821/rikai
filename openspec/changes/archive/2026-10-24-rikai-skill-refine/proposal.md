## Why

対象 issue: #8。

実際に使うと、次の4点が不便だった。

- 前回の問いに返答しないターンでも回答番号が進む。回答番号は、返答のあったターンの通番として読みたい。
- レポートをファイルに保存していても、チャットに同じレポートが出る。ファイルを直接読めば足りるので、邪魔になる。
- 回答番号を進めないターンが出ると、通常チャットの偶奇による判定では、同じ種別の問いが続く。
- クイズの直後に、入力欄のサジェストが答えを示す。

サジェストは Claude Code 本体の機能で、スキルや hooks から制御する手段は、公式ドキュメントで確認できなかった。そのため、スキルでは対処せず、README の案内にとどめる。

`.rikai/.gitignore` の自動作成は、#6 で扱う。この change には含めない。

## What Changes

- 返答も、仮説も、詳細を詰める型の質問もないターンでは、回答番号を進めない。レポートと問いは、これまでどおり出す。前回の問いは「返答なし」として黙って記録し続ける（記録の規則は変えない）。
- 起動と同じ発言に含まれる依頼への回答は、数える（回答番号 1）。
- 通常チャットの質問提案とクイズの別を、回答番号の偶奇から、「直前に出した問いの種別と逆」に変える。最初の問いは質問提案にする。Claude Code の乱数による選択は変えない。
- ファイル保存中は、通常のターンで、理解度レポートも保存先の案内もチャットに出さない。終了の応答では、最終レポートの代わりに、保存したファイルのパスを1行で並べる。**BREAKING**: 「ファイルに保存してもチャットにレポートを出す」という要件を、逆にする。
- README の「他のスキルとの併用」に、入力欄のサジェストがクイズの答えを示すときは、`promptSuggestionEnabled: false` で無効にできる旨を足す。あわせて、通常チャットの質問提案とクイズの別の説明を、新しい決め方に直す。
- `skills/rikai/SKILL.md` に、上の変更を反映する。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `rikai-question-selection`: 回答番号の進め方（数えないターン、起動と同じ発言）、通常チャットでの質問提案とクイズの別の決め方
- `rikai-session-mode`: 毎回の出力の規則（数えないターンの扱い、ファイル保存中のレポートの出力）、1ターンの処理の流れ、終了の応答（ファイル保存中のパスの並べ方）、起動の応答の回答番号の記述
- `rikai-understanding-report`: ファイル保存時にチャットへレポートを出す要件の変更、雛形の回答番号の記述
