# rikai-question-selection Specification

## Purpose
AIの回答ごとの理解の確認と促進のため、毎回の問いを質問提案とクイズから1問だけ選び、種別を機械的に決め、種類と形式を回答内容に合わせる。
## Requirements
### Requirement: 毎回1問だけ出す
rikai は、毎回、質問提案とクイズのどちらか1問だけを出さなければならない（SHALL）。（確定）

- 質問提案: ユーザーが次に投げるとよい質問、または自分の言葉での言い換えの依頼を1件提示する。質問はユーザー目線の文で書く。
- クイズ: ユーザーがAIの回答を理解しているかを確かめる問いを1問出す。

#### Scenario: 毎回の問い
- **WHEN** rikai が回答に問いを付ける
- **THEN** 質問提案またはクイズのどちらか1問だけを出す

### Requirement: 質問提案は理解していない前提で種類を選ぶ
質問提案は、回答内容をユーザーが理解していないことを前提にしなければならない（SHALL）。次のどちらかを、回答に最も合う形で1件選ばなければならない（SHALL）。（確定）

- 詳細を詰める
  - ○○は何？
  - ○○ってどこ？
  - ○○ってどういう仕組み？
  - なぜ○○？
  - 具体的には？
- オウム返しで確認
  - ユーザーが「○○って△△ってこと？」の形で、自分の言葉で言い換えて確認する。
  - AIは△△を埋めず、言い換えを促す一文だけを提示する。（既定）

#### Scenario: 詳細を詰める
- **WHEN** 回答に最も合う質問提案が、詳細を詰める形である
- **THEN** 「○○は何？」「○○ってどこ？」「○○ってどういう仕組み？」「なぜ○○？」「具体的には？」のいずれかを1件提示する

#### Scenario: オウム返しで確認
- **WHEN** 回答に最も合う質問提案が、オウム返しで確認する形である
- **THEN** △△を埋めず、ユーザーに自分の言葉での言い換えを促す一文だけを提示する

### Requirement: クイズの形式を回答内容に応じて選ぶ
rikai は、クイズの形式を、AIの回答の内容に応じて選ばなければならない（SHALL）。（確定）

- 用語・事実: 選択式。選択肢に加えて理由も同時に答えてもらう。
- 仕組み・理由: 記述式。

出題元は、直前の回答を基本とする。（既定）

#### Scenario: 用語・事実を問うクイズ
- **WHEN** 出題内容が用語・事実である
- **THEN** 選択式で出し、選択肢に加えて理由も同時に答えてもらう

#### Scenario: 仕組み・理由を問うクイズ
- **WHEN** 出題内容が仕組み・理由である
- **THEN** 記述式で出す

### Requirement: 質問提案とクイズの別と回答番号を決める
rikai は、質問提案とクイズのどちらを出すかを、機械的に選ばなければならない（SHALL）。（確定）

- Claude Code では、スクリプトが乱数を引いて選択結果（質問提案かクイズか）を出力する。乱数が 0.5 以上なら質問提案、0.5 未満ならクイズとする。（閾値と向きは既定）
- スクリプトが使えない環境では、直前に出した問いの種別と逆にする。直前が質問提案ならクイズ、クイズなら質問提案とする。起動後の最初の問いは、質問提案とする。（確定。回答番号を進めないターンが出ても、同じ種別が続かないようにするため）

「直前に出した問い」は、乱数で決めた問いも含め、そのモードで最後に出した問いとする。終了後に再び起動したときは、直前の問いは無いものとして、最初の問いから数え直す。（確定）

「スクリプトが使えない」とは、次のいずれかである。（確定）

- Bash ツールが無い環境（通常チャット）。最初から直前の問いの逆で決める。
- `pick.mts` の実行が失敗した場合。原因は問わない（Node が無い、スクリプトのエラー、実行が許可されなかった場合を含む）。
- `pick.mts` の出力が `suggestion` でも `quiz` でもない場合。

失敗した場合は、ユーザーには何も出さず、そのターンは直前の問いの逆で決める。次のターンは、あらためて `pick.mts` を試す。連続2回失敗したら、そのセッションでは以後 `pick.mts` を試さず、直前の問いの逆のみで決める。成功した場合は、連続の失敗の数を 0 に戻す。（確定。失敗が続く環境で、毎ターン失敗する呼び出しと権限プロンプトが繰り返されることを避ける）

回答番号は、rikai の起動後の回答のうち、数えるものに付ける会話全体の通番とする。数えるのは、ユーザーの発言に、前回の問いへの返答（クイズの回答、提案された質問、言い換え）、問いとは無関係な仮説、詳細を詰める型の質問のいずれかが含まれるターンの回答である。通番は表示用なので、数えるかの判定に迷ったときは、数えなくてよい。（既定）これらのどれも含まれないターンの回答は、数えない（番号を進めない。回答本文、レポート、問いはこれまでどおり出す）。ただし、新しく起動したときの、起動と同じ発言に含まれる依頼への回答は、返答も仮説も含まなくても数える。二重起動の発言に含まれる依頼への回答は、この例外に当たらず、上の条件で判定する。（確定）

起動後の最初に数える回答を 1 とし、以後は直前に数えた回答の番号に 1 を足す。起動の応答、二重起動の応答、終了の応答も数えない。ユーザーの発言1回につき、数えるターンの最終の回答を1つ数え、ツール実行中の中間メッセージは数えない。話題が分かれても番号は共有する。終了後に再び起動したときは、1 から数え直す。終了の応答の最終レポートには、直前に数えた回答の番号を書く。（確定）

機械選択の対象は、質問提案とクイズの別だけである。質問提案の中の種類とクイズの形式は、内容に応じてAIが選ぶ。（既定）会話圧縮や `/clear` の後に回答番号と直前の問いを維持できるかは未決である。

#### Scenario: 乱数が閾値と等しい
- **WHEN** Claude Code で、引いた乱数が 0.5 である
- **THEN** 質問提案を出す

#### Scenario: 乱数が閾値未満
- **WHEN** Claude Code で、引いた乱数が 0.5 未満である
- **THEN** クイズを出す

#### Scenario: 通常チャットで直前の問いが質問提案
- **WHEN** 通常チャットで、直前に出した問いが質問提案である
- **THEN** クイズを出す

#### Scenario: 通常チャットで直前の問いがクイズ
- **WHEN** 通常チャットで、直前に出した問いがクイズである
- **THEN** 質問提案を出す

#### Scenario: 通常チャットで回答番号を進めないターンが続く
- **WHEN** 通常チャットで、回答番号を進めないターンが続き、そのたびに問いを出す
- **THEN** 質問提案とクイズを交互に出し、同じ種別を続けて出さない

#### Scenario: pick.mts の実行が1回失敗した
- **WHEN** Claude Code で `pick.mts` の実行が失敗する
- **THEN** ユーザーには何も出さず、そのターンは直前の問いの種別と逆で決める。次のターンは、あらためて `pick.mts` を試す

#### Scenario: pick.mts の実行が連続2回失敗した
- **WHEN** Claude Code で `pick.mts` の実行が連続2回失敗する
- **THEN** そのセッションでは以後 `pick.mts` を試さず、直前の問いの種別と逆のみで決める

#### Scenario: pick.mts の出力が不正
- **WHEN** `pick.mts` の出力が `suggestion` でも `quiz` でもない
- **THEN** 実行の失敗と同じ扱いで、そのターンだけ直前の問いの種別と逆で決める

#### Scenario: 起動後の最初の問い
- **WHEN** rikai を起動した後、最初の問いを出し、スクリプトが使えない
- **THEN** 質問提案を出す

#### Scenario: 起動と同じ発言への回答
- **WHEN** 新しく起動するときに、「rikaiを始めて。Xを説明して」のように、起動と同じ発言に依頼が含まれる
- **THEN** その依頼への回答は、返答も仮説も含まなくても数え、回答番号は 1 になる

#### Scenario: 二重起動の発言に含まれる依頼
- **WHEN** すでに有効なときに、「rikaiを始めて。Xを説明して」のように、二重起動の発言に依頼が含まれ、返答も仮説も含まれない
- **THEN** 状態をリセットせず、この依頼への回答は数えない（回答番号を進めない）

#### Scenario: 返答も仮説も質問も含まないターン
- **WHEN** 起動後の2回目以降で、ユーザーの発言に、前回の問いへの返答も、問いとは無関係な仮説も、詳細を詰める型の質問も含まれない
- **THEN** 回答番号を進めない。回答本文、レポート、問いは通常どおり出す

#### Scenario: 返答を含むターン
- **WHEN** ユーザーの発言に、前回の問いへの返答が含まれる
- **THEN** 回答番号を1進める

#### Scenario: 回答番号に数えない応答
- **WHEN** 起動の応答、二重起動の応答、または終了の応答を返す
- **THEN** 回答番号に数えない。終了の応答の最終レポートには、直前に数えた回答の番号を書く
