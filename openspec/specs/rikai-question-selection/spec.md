# rikai-question-selection Specification

## Purpose
AIの回答ごとの理解の確認と促進のため、毎回の問いを質問提案とクイズから1問だけ選び、種別を機械的に決め、種類と形式を回答内容に合わせる。
## Requirements
### Requirement: 毎回1問だけ出す
rikai は、毎回、質問提案とクイズのどちらか1問だけを出さなければならない（SHALL）。（確定）

- 質問提案: ユーザーが次に投げるとよい質問、または自分の言葉での言い換えの依頼を1件提示する。質問はユーザー目線の文で書く。
- クイズ: ユーザーがAIの回答を理解しているかを確かめる問いを1問出す。

#### Scenario: 毎回の問い
- **WHEN** rikai が回答に問いを付ける
- **THEN** 質問提案またはクイズのどちらか1問だけを出す

### Requirement: 質問提案とクイズの別を機械的に選ぶ
rikai は、質問提案とクイズのどちらを出すかを、機械的に選ばなければならない（SHALL）。（確定）

- Claude Code では、スクリプトが乱数を引いて選択結果（質問提案かクイズか）を出力する。乱数が 0.5 以上なら質問提案、0.5 未満ならクイズとする。（閾値と向きは既定）
- スクリプトが使えない環境では、回答番号の偶奇で決め、奇数は質問提案、偶数はクイズとする。（既定）

「スクリプトが使えない」とは、次のいずれかである。（確定）

- Bash ツールが無い環境（通常チャット）。最初から偶奇で決める。
- `pick.mts` の実行が失敗した場合。原因は問わない（Node が無い、スクリプトのエラー、実行が許可されなかった場合を含む）。
- `pick.mts` の出力が `suggestion` でも `quiz` でもない場合。

失敗した場合は、ユーザーには何も出さず、そのターンは偶奇で決める。次のターンは、あらためて `pick.mts` を試す。連続2回失敗したら、そのセッションでは以後 `pick.mts` を試さず、偶奇のみで決める。成功した場合は、連続の失敗の数を 0 に戻す。（確定。失敗が続く環境で、毎ターン失敗する呼び出しと権限プロンプトが繰り返されることを避ける）

回答番号は、rikai の起動後の回答に付ける会話全体の通番とする。起動後の最初の回答を 1 とし、以後は直前の回答の番号に 1 を足す。起動の応答、二重起動の応答、終了の応答は数えない。ユーザーの発言1回につき最終の回答を1つ数え、ツール実行中の中間メッセージは数えない。話題が分かれても番号は共有する。終了後に再び起動したときは、1 から数え直す。終了の応答の最終レポートには、直前の回答の番号を書く。（確定）

機械選択の対象は、質問提案とクイズの別だけである。質問提案の中の種類とクイズの形式は、内容に応じてAIが選ぶ。（既定）会話圧縮や `/clear` の後に回答番号を維持できるかは未決である。

#### Scenario: 乱数が閾値と等しい
- **WHEN** Claude Code で、引いた乱数が 0.5 である
- **THEN** 質問提案を出す

#### Scenario: 乱数が閾値未満
- **WHEN** Claude Code で、引いた乱数が 0.5 未満である
- **THEN** クイズを出す

#### Scenario: 通常チャットで回答番号が奇数
- **WHEN** 通常チャットで、回答番号が奇数である
- **THEN** 質問提案を出す

#### Scenario: 通常チャットで回答番号が偶数
- **WHEN** 通常チャットで、回答番号が偶数である
- **THEN** クイズを出す

#### Scenario: pick.mts の実行が1回失敗した
- **WHEN** Claude Code で `pick.mts` の実行が失敗する
- **THEN** ユーザーには何も出さず、そのターンは回答番号の偶奇で決める。次のターンは、あらためて `pick.mts` を試す

#### Scenario: pick.mts の実行が連続2回失敗した
- **WHEN** Claude Code で `pick.mts` の実行が連続2回失敗する
- **THEN** そのセッションでは以後 `pick.mts` を試さず、回答番号の偶奇のみで決める

#### Scenario: pick.mts の出力が不正
- **WHEN** `pick.mts` の出力が `suggestion` でも `quiz` でもない
- **THEN** 実行の失敗と同じ扱いで、そのターンだけ回答番号の偶奇で決める

#### Scenario: 起動後の最初の回答
- **WHEN** rikai を起動した後、最初の回答を返す
- **THEN** 回答番号は 1 で、通常チャットでは質問提案を出す

#### Scenario: 回答番号に数えない応答
- **WHEN** 起動の応答、二重起動の応答、または終了の応答を返す
- **THEN** 回答番号に数えない。終了の応答の最終レポートには、直前の回答の番号を書く

### Requirement: 質問提案は理解していない前提で種類を選ぶ
質問提案は、回答内容をユーザーが理解していないことを前提にしなければならない（SHALL）。次のどちらかを、回答に最も合う形で1件選ばなければならない（SHALL）。（確定）

- 詳細を詰める
  - ○○は何？
  - ○○ってどこ？
  - ○○ってどういう仕組み？
  - なぜ○○？
  - 具体的には？
- オウム返しで確認
  - ユーザーが「○○って△△ってこと？」の形で、自分の言葉で言い換えて確認する。
  - AIは△△を埋めず、言い換えを促す一文だけを提示する。（既定）

#### Scenario: 詳細を詰める
- **WHEN** 回答に最も合う質問提案が、詳細を詰める形である
- **THEN** 「○○は何？」「○○ってどこ？」「○○ってどういう仕組み？」「なぜ○○？」「具体的には？」のいずれかを1件提示する

#### Scenario: オウム返しで確認
- **WHEN** 回答に最も合う質問提案が、オウム返しで確認する形である
- **THEN** △△を埋めず、ユーザーに自分の言葉での言い換えを促す一文だけを提示する

### Requirement: クイズの形式を回答内容に応じて選ぶ
rikai は、クイズの形式を、AIの回答の内容に応じて選ばなければならない（SHALL）。（確定）

- 用語・事実: 選択式。選択肢に加えて理由も同時に答えてもらう。
- 仕組み・理由: 記述式。

出題元は、直前の回答を基本とする。（既定）

#### Scenario: 用語・事実を問うクイズ
- **WHEN** 出題内容が用語・事実である
- **THEN** 選択式で出し、選択肢に加えて理由も同時に答えてもらう

#### Scenario: 仕組み・理由を問うクイズ
- **WHEN** 出題内容が仕組み・理由である
- **THEN** 記述式で出す
