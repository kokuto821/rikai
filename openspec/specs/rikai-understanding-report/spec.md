# rikai-understanding-report Specification

## Purpose
ユーザーの理解の現状を示し、前回のレポートを前提に更新できるようにするため、理解度レポートの項目・形式・スコープ・雛形・保存時の扱いを定める。
## Requirements
### Requirement: レポートの出力項目
rikai は、理解度レポートに次の項目を出力しなければならない（SHALL）。（確定）

- 必須
  - 理解した箇所
  - 一部理解した箇所
  - 理解できてない箇所
  - AIから解説されたがユーザーからの返答がない箇所
- 任意
  - 進めているタスクや調べ物の概要

#### Scenario: 必須項目の出力
- **WHEN** rikai が理解度レポートを出力する
- **THEN** 理解した箇所、一部理解した箇所、理解できてない箇所、AIから解説されたがユーザーからの返答がない箇所の4項目を含める

### Requirement: レポートの形式と更新
rikai は、理解度レポートを、デフォルトではチャット内の Markdown コードブロックとして出力しなければならない（SHALL）。代替として、Markdown ファイル `.rikai/<topic>-rikai-report.md` に保存できなければならない（SHALL）。形式は起動時にユーザーへ提案する。毎回、前回のレポートを前提に更新しなければならない（SHALL）。（確定）

#### Scenario: デフォルトの形式
- **WHEN** ユーザーが形式を選ばない
- **THEN** チャット内の Markdown コードブロックで出力する

#### Scenario: ファイルへの保存
- **WHEN** ユーザーが Markdown ファイルでの保存を選ぶ
- **THEN** `.rikai/<topic>-rikai-report.md` に保存する

#### Scenario: 前回のレポートの更新
- **WHEN** 前回のレポートが存在する状態で、新しいレポートを出力する
- **THEN** 前回のレポートを前提に更新する

### Requirement: レポートを話題単位で分割する
rikai は、レポートを機能・話題単位で作らなければならない（SHALL）。話題が変わったとAIが判断したら、「新レポート: <topic>」と1行で通知して分割しなければならない（SHALL）。ユーザーは訂正できる。戻ってきた話題は、既存レポートを再開しなければならない（SHALL）。ファイル保存時は `.rikai/` を検索する。（確定）

#### Scenario: 話題が変わった場合
- **WHEN** 話題が変わったとAIが判断する
- **THEN** 「新レポート: <topic>」と1行で通知し、レポートを分割する

#### Scenario: 話題が戻ってきた場合
- **WHEN** 以前の話題に戻ってくる
- **THEN** 新しく作らず、その話題の既存レポートを再開する

#### Scenario: ファイル保存時の再開
- **WHEN** ファイル保存の環境で、以前の話題に戻ってくる
- **THEN** `.rikai/` を検索して既存レポートを探す

### Requirement: レポートの雛形
rikai は、理解度レポートを次の雛形に沿って出力しなければならない（SHALL）。（既定）`回答番号` には、レポートを出す時点で最後に数えた回答の番号を書く。回答番号を進めないターンでは、番号は前回のまま変わらない。出さなかった話題のレポートの番号は、古いままでよい。終了の応答の最終レポートには、直前に数えた回答の番号を書く（終了の応答は番号に数えないため）。通番の定義は rikai-question-selection に従う。（確定）

````markdown
# 理解度レポート: <話題>
回答番号: N
概要: <任意>

## 理解した箇所
- ...

## 一部理解した箇所
- ... （不足: ...）

## 理解できてない箇所
- ...

## AIから解説されたがユーザーからの返答がない箇所
- ...
````

#### Scenario: 雛形に沿った出力
- **WHEN** rikai が理解度レポートを出力する
- **THEN** 話題名、回答番号、概要（任意）、4つの項目の順で、雛形に沿って出力する

#### Scenario: 話題が複数あるときの回答番号
- **WHEN** 話題が複数に分かれているときにレポートを出力する
- **THEN** 出力するレポートには、出力時点で最後に数えた回答の番号を書き、出力しなかった話題のレポートの番号は変えない

#### Scenario: 回答番号を進めないターンのレポート
- **WHEN** 回答番号を進めないターンで、レポートを出力する
- **THEN** 回答番号は前回のレポートと同じ番号のままで、前回の問いが残っていれば、「返答なし」の記録だけが反映される

### Requirement: ファイル保存時に .rikai/.gitignore を作って個人領域にする
ファイルへ保存する場合、rikai は、`.rikai/` を個人領域として扱わなければならない（SHALL）。初めて `.rikai/` を作るとき、同時に `.rikai/.gitignore` を作り、中身は `*` の1行にする（SHALL）。`.rikai/` は、作業ディレクトリ（リポジトリ直下とは限らない）の直下に置く。作ったときは、`.rikai/.gitignore` を作ったこと、レポートが git の対象外になったこと、追跡したいときはこのファイルを削除すればよいことを、1行で通知しなければならない（SHALL）。（確定）

`.rikai/` がすでにあれば、`.rikai/.gitignore` を作らず、通知も出してはならない（SHALL NOT）。上書きも、作り直しもしない。`.rikai/.gitignore` が無い場合や、ユーザーが削除したあとも、作らない。レポートの保存は続ける。追跡したいユーザーは、`.rikai/.gitignore` を削除すればよい。（確定）

`.rikai/.gitignore` は、レポートより先に作る。作れなかったときは、レポートの書き込みに失敗したときと同じに扱う。つまり、そのターンのレポートはファイルに書かず、チャットに出し、失敗した旨を1行で付随の通知として伝えなければならない（SHALL）。この場合、「作った」という通知は出さない。（既定）

リポジトリ直下の `.gitignore` は、自動編集してはならない（SHALL NOT）。（確定）

#### Scenario: 初回のファイル保存
- **WHEN** 初めてレポートをファイルに保存し、作業ディレクトリの直下に `.rikai/` が無い
- **THEN** `.rikai/` と同時に、中身が `*` の1行の `.rikai/.gitignore` を作り、作った旨を1行で通知する。リポジトリ直下の `.gitignore` は編集しない

#### Scenario: .rikai/ がすでにある
- **WHEN** ファイルに保存するとき、`.rikai/` がすでにある
- **THEN** `.rikai/.gitignore` を作らず、上書きもしない。通知も出さない

#### Scenario: .rikai/.gitignore を作れなかった
- **WHEN** 初めてのファイル保存で、`.rikai/.gitignore` を作れない
- **THEN** そのターンのレポートはファイルに書かずチャットに出し、失敗した旨を1行で伝える。「作った」という通知は出さない

#### Scenario: .rikai/.gitignore を消したあとの保存
- **WHEN** ユーザーが `.rikai/.gitignore` を削除したあと、レポートを保存する
- **THEN** `.rikai/.gitignore` を作り直さない

### Requirement: レポートの項目は1箇所1行で更新する
rikai は、レポートを更新するとき、項目の書き方と移動を次の暫定ルールに従って扱わなければならない（SHALL）。（既定。暫定）

- 1つの箇所は1行で書く。
- 再判定で結果が変わったら、元の項目から削除して、新しい項目に移す。同じ箇所を複数の項目に残さない。
- 項目数の上限は決めない。

レポート項目の遷移規則の詳細（例: 理解できてない → 後で一致 → 理解した の扱い）と、重複排除、レポートが伸び続けないための上限は未決である。

#### Scenario: 再判定で結果が変わった
- **WHEN** 「理解できてない」とした箇所を、後の返答で一致と判定する
- **THEN** 「理解できてない箇所」から削除し、「理解した箇所」に1行で移す

### Requirement: ファイル名の話題名を安全な名前にする
ファイルへ保存する場合、rikai は、`.rikai/<topic>-rikai-report.md` の `<topic>` を、次の規則で作らなければならない（SHALL）。（確定）

- 日本語、英数字、`-`、`_` はそのまま使う。スラッシュ、`..`、空白、その他の記号は `-` に置き換える。先頭と末尾の `-` は取り除き、連続する `-` は1つにまとめる。`.rikai/` の外に書き込まれないようにするため。
- 長い話題名は、短い名詞句に縮める（目安は30文字程度）。レポート内の見出し `# 理解度レポート: <話題>` には、元の話題名をそのまま書く。
- 同じ名前のレポートがすでにあり、同じ話題なら、既存レポートを再開する。話題が違うのに名前だけ衝突した場合は、末尾に `-2` を付けて区別する。
- 既存レポートを再開するときの検索は、ファイル名の一致ではなく、`.rikai/` 内のレポートの見出しの話題名で探す。

#### Scenario: 記号を含む話題名
- **WHEN** 話題名に、スラッシュや空白などの記号が含まれる
- **THEN** それらを `-` に置き換えたファイル名で保存し、見出しには元の話題名を書く

#### Scenario: 名前だけが衝突する別の話題
- **WHEN** 別の話題だが、`<topic>` が既存のレポートと同じになる
- **THEN** 末尾に `-2` を付けたファイル名で保存する

#### Scenario: 既存レポートの再開
- **WHEN** 以前の話題に戻り、ファイル保存の環境である
- **THEN** `.rikai/` 内のレポートの見出しの話題名で既存のレポートを探して再開する

### Requirement: ファイルに保存している間はチャットにレポートを出さない
ファイルへ保存している間、rikai は、理解度レポートも保存先の案内も、チャットに出してはならない（SHALL NOT）。レポートはファイルに書き込み、内容はファイルで確認できるようにする。判定結果と問いは、保存の有無にかかわらず出す。（確定）出力順は rikai-session-mode に従う。

書き込みに失敗したときだけ、そのターンのレポートをチャットに出し、失敗した旨を1行で伝えなければならない（SHALL）。この1行は、付随の通知として、回答本文の直前に置く。終了の応答は別の扱いとする（下の段落）。前回のレポートは、会話の中で直近に書き込んだ内容を前提にする。書き込みに失敗したときは、チャットに出した内容を前提にする。前回のレポートの内容が会話から分からなければ、ファイルを読み直す。（既定）

「保存先の案内」は、保存先のパスや、保存したことを知らせる通知を指す。初回保存時の、`.rikai/.gitignore` を作ったことを知らせる1行は、保存先の案内ではなく、付随の通知であり、この規則の対象外とする。「新レポート: <topic>」の通知も付随の通知であり、保存中も出す。（確定）

終了の応答では、最終の判定をファイルに反映してから、全話題の最終レポートの代わりに、保存した全話題のレポートのファイルのパスを、1行にまとめて並べなければならない（SHALL）。反映に失敗したときは、最終レポートをチャットに出す。（確定）

保存に切り替えたターンから、この規則を適用する。切り替えより前の全話題の内容は、その時点のレポートとしてファイルに書き出す。（既定）

#### Scenario: ファイル保存中の通常のターン
- **WHEN** ファイルへの保存を選んだ状態で、レポートを更新する
- **THEN** ファイルを更新し、レポートも保存先の案内もチャットには出さない。判定結果と問いは出す

#### Scenario: ファイルへの書き込みに失敗した
- **WHEN** ファイルへの保存を選んだ状態で、書き込みに失敗する
- **THEN** そのターンだけ、レポートをチャットに出し、失敗した旨を1行で伝える

#### Scenario: ファイル保存中の終了の応答
- **WHEN** ファイルへの保存を選んだ状態で、ユーザーが終了を命じる
- **THEN** 最終の判定をファイルに反映し、最終レポートの代わりに、保存した全話題のレポートのファイルのパスを、1行にまとめて並べる

#### Scenario: 保存に切り替えたターン
- **WHEN** チャット内表示で進めていて、ユーザーがファイルへの保存を選ぶ
- **THEN** それまでの全話題の内容をその時点のレポートとしてファイルに書き出し、そのターンから、レポートをチャットに出さない
