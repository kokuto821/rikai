# rikai 評価ケース

別エージェントが起草し、別のエージェントが仕様の本文と照らして見直した。SKILL.md の実装ではなく、README.md と `openspec/specs/` から期待挙動を導いた。

- `evals.json`: 起動後の振る舞いを1ターンで測るケース15件（起動と依頼、クイズへの返答、詳細を詰める質問、話題の切り替え、終了、英語での起動と依頼、日本語の会話の途中での英語の返答、英語の用語を混ぜた日本語での起動、日本語を引用した英語での起動、英語の会話での話題の切り替え、英語の会話での終了、手がかりの無い起動、英語でのクイズへの返答（一部理解）、英語の会話の途中での日本語への切り替え、英語での詳細を詰める質問）。6〜15件目は #30 で、`rikai-session-mode` の「出力の言語をユーザーの発言の言語に合わせる」と、`rikai-understanding-report` の「レポートの雛形」から導いて足した。skill-creator の schemas.md の形式（`skill_name` / `evals[].id, prompt, expected_output, files, expectations`）。セッション途中の状態は、prompt 内に会話の要約として埋め込む。
- `trigger-evals.json`: description 最適化用。`{query, should_trigger}` の配列で、true 6件・false 9件。false には、近接ケース（rikai自体の開発、一回きりのクイズ作成、面接練習、eval作成の依頼）を含める。

## 1ターンで測れない性質（evals.json では未検証）

- セッション持続（会話圧縮や `/clear` での失効、終了後の無出力）
- pick.mts の乱数による質問提案とクイズの別、連続2回失敗の代替ロジック（通常チャットの交互ルールは複数ターン要る）
- 話題への復帰（既存レポートの再開）、`.rikai/` のファイル保存と `.gitignore` 作成（ファイル書き込み環境が要る）
- 言語が変わったときのファイルの書き直しと、ファイル名を変えないこと、別の言語の見出しのレポートの再開（ファイル書き込み環境が要る）
- ターンをまたいで、訳の文言を変えないこと（10・11・13・15件目は、prompt に埋め込んだ見出しの「Understanding report」との一致だけを測る）
- 判定の正誤そのもの（AIの解釈との一致度は主観が入る）
