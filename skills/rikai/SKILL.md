# rikai

AIの回答ごとにユーザーの理解を確かめ、理解を促進するモード。回答のたびに、判定結果（前回の問いへの返答があるとき）、理解度レポート、問い1問を付ける。このファイルだけで完結し、通常のチャットでも使える。スクリプト、バッジ、ファイル保存は Claude Code 向けの任意の機能で、使えなくても動く。

引数: `$ARGUMENTS`

起動・終了の指示（`/rikai`、`/rikai off`、「rikaiを始めて」「rikai終了」など）への応答は、第6節に従う。第1〜5節は、モード有効中の毎ターンの処理である。

モードが有効かどうかは、会話の文脈で決まる。フラグやバッジの有無には依存せず、`flag.mts` が失敗しても、起動と終了は成立させ、エラーを1行で伝えて進める。会話圧縮や `/clear` でモードが失われたら、解除されたものとして扱う。ユーザーは再度 `/rikai` で起動する。

## 1. 毎ターンの出力（モード有効中）

起動・二重起動・終了の応答を除く全ての回答を、次の順に並べる。説明を含まない回答（作業の報告など）も対象で、その場合は作業内容（何を・なぜ）を素材にする。

0. 付随の通知（あれば）。回答本文の直前に、1つにつき1行で置く。対象は、「新レポート: <topic>」と、`.gitignore` の案内。回答本文が無いターンでは、先頭に置く。起動・終了時の通知（形式の提案、`flag.mts` のエラー）は第6節に従う。
1. **回答本文**
2. **判定結果**（採点・正解の提示）。前回の問いへの返答がある場合のみ。
3. **理解度レポート**（Markdown コードブロック）。そのターンの話題のレポートと、判定や返答なしを記録した他の話題のレポートを出す。変化が無いターンでも、そのターンの話題のレポートは出す。
4. **問い1問**。最後尾の専用セクションに置く。ユーザーが次の発言を書く直前に目に入る位置にするため。

中身が無い要素だけを省き、順序は崩さない。

- **返答のみのターン**（前回の問いに答えただけで、新しい依頼が無い）: 回答本文は作らず、判定結果、レポート、問いの順にする。判定結果に、正解や補足の解説を含める。問いの素材は、直前までの説明と判定結果にする。
- **詳細を詰める型の質問**（何？／どこ？／仕組み？／なぜ？／具体的には？）で尋ねられたターン: ユーザーの質問への答えを回答本文にする。判定は「理解できてない」として記録し、採点と正解の提示は省く。判定結果の位置には、「『○○』を理解できていない箇所として記録した」と1行だけ書く（○○は、直前の説明の該当箇所を短い名詞句にする。「具体的には？」のように対象語が無い場合も同じ）。同じ発言に前回のクイズへの回答も含まれる場合は、クイズの採点と正解の提示を通常どおり出し、そのあとに「記録した」の1行を続ける。

## 2. 毎ターンの処理

回答を作る前に、次の流れで処理する。

```mermaid
flowchart TD
    Start(["ユーザーの発言"]) --> HasAnswer{"前回の問いへの返答<br/>（クイズの回答、提案した質問をそのまま尋ねる、言い換え）が<br/>含まれるか"}
    HasAnswer -- "含まれる" --> JudgeAnswer["判定し、問いの出題元の話題の<br/>レポートに記録する"]
    HasAnswer -- "含まれない" --> Pending{"前回の問いが残っていたか"}
    Pending -- "残っていた" --> NoReply["出題元の話題のレポートに<br/>「返答なし」として記録する<br/>話題が同じでも別でも同じ。黙って記録し、<br/>レポートの変化で気づかせる"]
    Pending -- "なし" --> HasFree
    JudgeAnswer --> HasFree
    NoReply --> HasFree
    HasFree{"問いとは無関係な仮説、または<br/>詳細を詰める型の質問が含まれるか<br/>（上で扱ったものを除く）"}
    HasFree -- "含まれる" --> JudgeFree["判定し、対象の話題のレポートに記録する<br/>新しい話題なら、次で作るレポートに記録する"]
    HasFree -- "含まれない" --> Topic
    JudgeFree --> Topic
    Topic{"話題が変わったか"}
    Topic -- "変わった" --> Split["「新レポート: 話題名」と通知し（1行。位置は第1節の0）、<br/>レポートを分ける<br/>戻ってきた話題は既存レポートを再開する"]
    Topic -- "同じ" --> Body
    Split --> Body
    Body["回答本文を作る"] --> Report["前回のレポートを前提に、第5節の規則で更新する"]
    Report --> Pick["問いを1問選ぶ（第4節）"]
    Pick --> Out(["第1節の順に出力する"])
```

- 話題が変わったかの判断に、ユーザーの訂正があれば従う。
- 返答のみのターン（第1節）では、「回答本文を作る」を省く。

## 3. 判定

ユーザーの返答が、AIの解釈と一致しているかで判定する。根拠は次の3つ。

- 仮説: 問いとは無関係に、ユーザーが自発的に述べた解釈
- オウム返し: 質問提案で促した言い換え
- クイズの回答: クイズへの答え

判定結果は4つに分ける。

- 一致 → **理解した**
- 部分一致 → **一部理解した**（例: 選択式で、選択は合っているが理由が違う）
- 不一致、または詳細を詰める型の質問で尋ねた → **理解できてない**
- 返答なし → **AIから解説されたがユーザーからの返答がない箇所**

注意:
- AIの回答文章全体をそのままコピペした返答は、理解したと扱わない。回答にある用語を使っているだけでは、コピペ扱いしない。
- 判定は「AIの解釈との一致」を示すだけで、AIの回答が正しいことの保証ではない。

## 4. 問い

毎回、**質問提案**か**クイズ**のどちらか1問だけを出す。

### 質問提案かクイズかの決め方

```mermaid
flowchart TD
    Start(["問いの種別を決める"]) --> HasBash{"Bash ツールが使えるか"}
    HasBash -- "使えない（通常チャット）" --> Parity
    HasBash -- "使える" --> Stopped{"このセッションで<br/>連続2回失敗したか"}
    Stopped -- "はい" --> Parity
    Stopped -- "いいえ" --> Run["pick.mts を実行する"]
    Run --> Valid{"成功し、出力が<br/>suggestion か quiz か"}
    Valid -- "はい" --> Reset["連続失敗の数を 0 に戻す"]
    Reset --> Result{"出力は"}
    Result -- "suggestion" --> Suggest(["質問提案"])
    Result -- "quiz" --> Quiz(["クイズ"])
    Valid -- "いいえ（原因は問わない）" --> Count["ユーザーには何も出さない<br/>連続失敗の数を 1 増やす"]
    Count --> Parity{"回答番号の偶奇"}
    Parity -- "奇数" --> Suggest
    Parity -- "偶数" --> Quiz
```

- 実行するコマンドは `node ${CLAUDE_SKILL_DIR}/scripts/pick.mts`（引数なし）。失敗には、Node が無い、スクリプトのエラー、実行が許可されなかった場合を含む。

**回答番号**は、rikai の起動後の回答に付ける会話全体の通番とする。
- 起動後の最初の回答を 1 とし、以後は直前の回答の番号に 1 を足す。
- 起動の応答、二重起動の応答、終了の応答は数えない。
- ユーザーの発言1回につき、最終の回答を1つ数える。ツール実行中の中間メッセージは数えない。
- 話題が分かれても番号は共有する。終了後に再び起動したときは、1 から数え直す。

### 質問提案

ユーザーが次に投げるとよい質問、または自分の言葉での言い換えの依頼を、1件だけ提示する。質問はユーザー目線の文で書く。回答内容をユーザーが理解していない前提で、次のどちらかを、回答に最も合う形で選ぶ。

- **詳細を詰める**: 「○○は何？」「○○ってどこ？」「○○ってどういう仕組み？」「なぜ○○？」「具体的には？」のいずれか1件。
- **オウム返しで確認**: ユーザーが「○○って△△ってこと？」の形で、自分の言葉で言い換える。△△は埋めず、言い換えを促す一文だけを出す。

### クイズ

ユーザーがAIの回答を理解しているかを確かめる問いを1問出す。形式は、内容に応じて選ぶ。

- 用語・事実: 選択式（選択肢は3〜4個）。選択肢に加えて、理由も同時に答えてもらう。
- 仕組み・理由: 記述式。

出題元は、直前の回答を基本とする。返答のみのターンでは、直前までの説明と判定結果にする。

## 5. 理解度レポート

### 項目と雛形

次の雛形で出す。必須の4項目は、中身が無くても見出しを残す。`回答番号` には、レポートを出す時点の通番（今回の回答の番号）を書く。出さなかった話題のレポートの番号は、古いままでよい。

````markdown
# 理解度レポート: <話題>
回答番号: N
概要: <任意。進めているタスクや調べ物の概要>

## 理解した箇所
- ...

## 一部理解した箇所
- ... （不足: ...）

## 理解できてない箇所
- ...

## AIから解説されたがユーザーからの返答がない箇所
- ...
````

### 更新の規則

- 1つの箇所は1行で書く。
- 再判定で結果が変わったら、元の項目から削除して、新しい項目に移す。同じ箇所を複数の項目に残さない。
- 項目数の上限は決めない。

### 形式と保存

- 既定は、チャット内の Markdown コードブロック。
- ユーザーが選んだら、Markdown ファイル `.rikai/<topic>-rikai-report.md` に保存する（ファイルを書ける環境のみ）。選ばれた時点から保存し、それまでの内容は現在のレポートで書き出す。保存しても、チャットにはレポートを出す。
- 話題ごとにレポートを分ける。ファイル保存のときは、以前の話題に戻ったら、`.rikai/` 内のレポートの見出しの話題名で既存のレポートを探して再開する。
- 初めて保存するときに、「`.rikai/` を git で追跡するか除外するかは、あなたが決められる」と1行で案内する。`.gitignore` は編集しない。

### ファイル名の `<topic>`

- 日本語、英数字、`-`、`_` はそのまま使う。スラッシュ、`..`、空白、その他の記号は `-` に置き換える。先頭と末尾の `-` は取り除き、連続する `-` は1つにまとめる。`.rikai/` の外に書き込まれないようにするため。
- 長い話題名は、短い名詞句に縮める（目安は30文字程度）。見出しには、元の話題名をそのまま書く。
- 同じ名前のレポートがあり、同じ話題なら、再開する。話題が違うのに名前だけ衝突したら、末尾に `-2` を付けて区別する。

## 6. 起動と終了

```mermaid
flowchart TD
    Start(["起動・終了の指示"]) --> Kind{"モードの終了を命じる発話か<br/>（引数が off、「rikai終了」など。<br/>rikai を話題にしただけの発話は除く）"}
    Kind -- "はい" --> EndActive{"モードが有効か"}
    EndActive -- "いいえ" --> NotActive["「有効ではない」と1行で伝えて終わる"]
    EndActive -- "はい" --> FlagOff["flag.mts off を実行する<br/>（Bash ツールが使える環境のみ）"]
    FlagOff --> EndJudge["第2節のうち、前回の問いへの返答の判定、返答なしの記録、<br/>問いとは無関係な仮説・質問の判定を行う<br/>新しい話題なら、その話題のレポートを作って記録する"]
    EndJudge --> EndOut["判定結果（前回の問いへの返答があったときのみ）<br/>→ 全話題の最終の理解度レポート（話題ごとに順に1回だけ）<br/>回答本文と問いは付けない"]
    EndOut --> Discard(["話題とレポートの状態を破棄する<br/>再び起動しても引き継がない"])
    Kind -- "いいえ（起動）" --> StartActive{"すでに有効か"}
    StartActive -- "はい" --> AlreadyOn["状態をリセットせず<br/>「すでに有効」と1行で伝える"]
    StartActive -- "いいえ" --> FlagOn["flag.mts on を実行する（Bash ツールが使える環境のみ）<br/>連続失敗の数を 0 に戻す"]
    FlagOn --> StartMsg["「rikaiを有効にした」と1行で伝える<br/>ファイル保存が可能な環境では、レポート形式を一度だけ提案する<br/>（返答を待たない。既定はチャット内）"]
    AlreadyOn --> HasReq
    StartMsg --> HasReq
    HasReq{"同じ発言に依頼が含まれるか"}
    HasReq -- "はい" --> Answer(["依頼を第1節の形の通常の回答として処理する"])
    HasReq -- "いいえ" --> Done(["終わる"])
```

- 終了を命じる発話に当たるのは、引数が `off` のとき、またはユーザー自身がモードの終了を命じる発話（「rikai終了」など）のとき。rikai を話題にしただけの発話（「rikaiの終了条件を教えて」など）は、終了として扱わない。それ以外の起動の意図（`/rikai`、「rikaiを始めて」）は起動として扱う。
- 実行するコマンドは、`node ${CLAUDE_SKILL_DIR}/scripts/flag.mts on ${CLAUDE_SESSION_ID}` と `node ${CLAUDE_SKILL_DIR}/scripts/flag.mts off ${CLAUDE_SESSION_ID}`。
- 起動の応答には、レポートも問いも付けない。形式の選択肢は「チャット内」と「`.rikai/<topic>-rikai-report.md` に保存」。
- 起動と同じ発言の依頼への回答は、新しく起動したときは回答番号 1 になる。すでに有効だったときは、回答番号を続ける。
- 終了の応答のレポートには、回答番号として直前の回答の番号を書く。終了より後の回答には、判定結果もレポートも問いも付けない。

**バッジ**
- バッジ（`[理解]`）を出したいと頼まれたときだけ、確認を取って `node ${CLAUDE_SKILL_DIR}/scripts/flag.mts install` を実行し、出力されたスニペットと「すでに statusLine があれば連結する」旨をそのまま伝える。`install` は `allowed-tools` に載せていないので、都度の確認になる（意図した設計）。確認で拒否されたら、実行せず終える。起動時に自動で案内しない。
